# 周报规范

本文件定义 `uj-weekly-report` 的数据契约、写作口径和 Excel 模板。脚本和模型都以此为准。

## 1. 数据流

```text
git log
  -> commits.json     # 证据：谁、哪天、哪个仓库、哪条提交
  -> report.json      # 叙事：重点项目 / 日常工作、目标、进展、状态、偏差
  -> 个人周报.xlsx    # 交付：套用 UJoin 模板，只替换数据单元格
```

- `commits.json` 由 `scripts/extract_commits.py` 生成，不手改。
- `report.json` 由模型根据 `commits.json` 编写，是唯一需要人工/模型判断的中间产物。
- `.xlsx` 由 `scripts/render_report.py` 生成，不手改；改内容请改 `report.json` 后重新渲染。
- `scripts/validate_report.py` 负责覆盖、字段、证据和模板一致性校验。

`commits.json` 中的 `ignored` 不得被静默丢弃：

- `ignored` 只包含 `ignored_repos` 中符合作者和日期范围的本人提交。
- `stats.ignored_commit_count` 是这些提交的总数；`stats.ignored_repos_with_commits` 是有本人提交的仓库数。
- 生成 `report.json` 前必须审查并按需向用户说明 `ignored`。实际工作应改映射到 `projects`，只有明确不需要进入周报的仓库才保留在 `ignored_repos`。

## 2. 周期

- 默认周期：上一个 ISO 周，周一至周日。
- `period` 格式：`YYYY/MM/DD-YYYY/MM/DD`，例如 `2026/10/19-2026/10/25`。
- `week` 格式：`W43`；同时保留 `iso_year`，避免跨年周歧义。
- 单周模板要求起止日期落在同一个 ISO 周。跨周范围先和用户确认，不要直接套单周模板。

## 3. `report.json` 结构

```json
{
  "person_name": "张三",
  "period": "2026/10/19-2026/10/25",
  "week": "W43",
  "sections": [
    {
      "label": "重点项目",
      "items": [
        {
          "name": "示例平台接入与鉴权",
          "goal": "完成平台应用接入、租户白名单与网关鉴权能力。",
          "progress": "实现应用类别透传与租户列表返回；修复应用无角色时的处理；调整请求限制并补充鉴权主体字段说明。",
          "status": "✅已完成",
          "deviation": "",
          "evidence": {
            "projects": ["Example Platform"],
            "repos": ["platform", "packages/platform-gateway"],
            "commit_count": 6,
            "sample_commits": [
              "内部微服务豁免租户白名单并返回应用类别",
              "鉴权主体新增应用类别与租户列表",
              "修复应用无角色时处理"
            ]
          }
        }
      ]
    },
    {
      "label": "日常工作",
      "items": []
    }
  ]
}
```

### 字段契约

| 字段 | 必填 | 规则 |
|---|---|---|
| `person_name` | 否 | 标题和工作表名；优先用 `config.json` 的 `report.person_name`，都没有时回退 `员工姓名`。 |
| `period` | 是 | 必须与 `commits.json` 的 `period.label` 一致。 |
| `week` | 建议 | 必须与 `commits.json` 的 `period.week` 一致。 |
| `sections` | 是 | 必须且只能包含 `重点项目` 和 `日常工作` 两个 section。 |
| `label` | 是 | 固定为 `重点项目` / `日常工作`，渲染到 A 列。 |
| `items` | 是 | 每个 section 0-4 条；模板只有 4 个槽位。 |
| `name` | 是 | 8-30 字，写关键结果，不写仓库名，不写 commit 标题堆砌。 |
| `goal` | 是 | 一句话说明目标；重点项目优先使用项目映射里的标准 `goal`。 |
| `progress` | 是 | 2-5 个分句，用中文分号 `；` 分隔；动词开头；写具体技术名词。 |
| `status` | 是 | `✅已完成` / `🟡进行中` / `⏸暂停` / `❌延期`。 |
| `deviation` | 条件 | 非 `✅已完成` 时必填；`✅已完成` 时留空。 |
| `evidence.projects` | 是 | 对应项目名，必须出现在 `commits.json.stats.by_project` 中。 |
| `evidence.repos` | 建议 | 支撑条目的仓库路径，便于审计。 |
| `evidence.commit_count` | 是 | 支撑条目的提交数，必须大于 0，且不超过对应项目实际提交数。 |
| `evidence.sample_commits` | 是 | 1-5 条真实提交标题；单提交条目可为 1 条，其余建议 2-5 条。 |

## 4. 选材规则

### 重点项目（3-4 条）

满足任一条件：

- 战略性、功能级、跨多天或跨多仓库。
- 对用户可见，或涉及架构、协议、核心链路、数据迁移。
- 单个项目提交很多时，按主题拆成 2-3 条，而不是逐条罗列提交。

### 日常工作（2-4 条）

- 小修复、文档、配置、构建、环境维护。
- 单条或少量提交，但确实占用了工作时间。
- 不要为了凑数把重点项目拆成日常。

### 总量

最多 8 条，正好填满模板的 4+4 行。超过 8 条时优先合并同类项，模板不允许加行。

## 5. 完成状态口径

| 状态 | 使用条件 |
|---|---|
| `✅已完成` | 本周工作闭环，无遗留。 |
| `🟡进行中` | 已启动、按计划推进，但本周未闭环。 |
| `⏸暂停` | 因依赖、资源或优先级变化暂停。 |
| `❌延期` | 有阻塞、延期或范围变化。 |

状态不是 `✅已完成` 时，`deviation` 必须写原因，例如“等待第三方接口联调”“硬件环境未到位”“范围新增，顺延到下周”。

兼容旧写法：`完成` → `✅已完成`，`进行中` / `部分完成` → `🟡进行中`，`暂停` → `⏸暂停`，`有偏差` → `❌延期`。新报告直接写模板状态。

## 6. 写作规则

- 用中文书面语，不用第一人称。
- 不写 commit hash、分支名、内部工单号。
- 不写“相关工作”“其他优化”这类无法审计的表述。
- 不编造上线、发布、客户验收、性能指标；除非提交或用户明确提供。
- 优先写：表、接口、字段、页面、协议、模板、迁移、配置、链路。
- `progress` 用分号分隔，每个分句一个动作，避免长句套长句。
- 同一件事不要同时出现在重点项目和日常工作。

## 7. Excel 模板

### 唯一来源

`assets/ujoin-weekly-template.xlsx`，由 `ujoin周报模板.xlsx` 的“个人周报（模板）”工作表脱敏而来。

渲染器只写以下单元格，其余单元格、样式、合并、数据验证全部保持模板原样：

- `A1`：`个人周报——<姓名>`
- `A3`：`周报周期：<period>`
- `B5:F8`：重点项目 4 行
- `B9:F12`：日常工作 4 行

### 行结构

| 行 | 内容 | 合并 |
|---|---|---|
| 1 | `个人周报——<姓名>` | A1:F1 |
| 2 | 填写说明 | A2:F2 |
| 3 | `周报周期：YYYY/MM/DD-YYYY/MM/DD` | A3:F3 |
| 4 | 表头 6 列 | 无 |
| 5-8 | 重点项目，固定 4 行 | A5:A8 |
| 9-12 | 日常工作，固定 4 行 | A9:A12 |
| 13 | 第二张表的周期占位 | A13:F13 |
| 14 | 第二张表的表头 | 无 |
| 15-18 | 第二张表的重点项目，空白 | A15:A18 |
| 19-22 | 第二张表的日常工作，空白 | A19:A22 |

### 样式

| 元素 | 样式 |
|---|---|
| 标题 | `1F4E79` 底、白字、16 号加粗、居中、合并 A1:F1 |
| 说明 | 10 号、自动换行、垂直居中、合并 A2:F2 |
| 周期 | `C7DCFF` 底、`404040` 字、10 号、居中、合并 A3:F3 |
| 表头 | `FFF2CC` 底、10 号加粗、细边框 `BFBFBF`、居中换行 |
| 重点项目标签 | `2E75B6` 底、白字、10 号加粗、竖排、居中 |
| 日常工作标签 | `548235` 底、白字、10 号加粗、竖排、居中 |
| 数据单元格 | 10 号、细边框、垂直居中、自动换行；E 列水平居中 |
| 行高 | 不设置，由 Excel 自动撑开 |

### 列宽

| 列 | 宽度 |
|---|---|
| B | 23.0625 |
| C | 37.5312 |
| D | 61.3203 |
| A / E / F | 默认宽度 |

### 页面

- 保持模板默认：不设置纸张方向、纸张大小、缩放、打印标题。
- 网格线显示。
- 页边距：左 0.75、右 0.75、上 1.0、下 1.0 英寸。

### 数据验证

`E5:E12` 和 `E15:E22` 的下拉列表：

```text
✅已完成,🟡进行中,⏸暂停,❌延期
```

## 8. 校验规则

### 错误（必须修复）

- `period` 与 `commits.json` 不一致。
- `unmapped` 非空。
- 有提交的项目没有被任何条目的 `evidence.projects` 覆盖。
- `sections` 不是 `重点项目` + `日常工作`。
- 某个 section 超过 4 条。
- 必填字段为空。
- `status` 不在允许值内（含兼容别名）。
- 非 `✅已完成` 但 `deviation` 为空。
- `evidence.commit_count <= 0`，或超过对应项目实际提交数。
- Excel 标题、说明、周期、表头、8 个合并区域、列宽、行高、数据验证与模板不一致。
- 任一单元格的字体、底色、边框、对齐与模板不一致。
- 第二张空白表被写入内容。
- 页面设置被改动。

### 警告（建议修复）

- `ignored` 非空：确认被 `ignored_repos` 排除的本人提交不属于本周报范围。
- 重点项目不在 3-4 条。
- 日常工作不在 2-4 条。
- 总条目超过 8 条。
- `sample_commits` 在提交记录中找不到对应标题。
- `✅已完成` 但 `deviation` 非空（`无` 会被视为空，不触发）。

## 9. 隐私与仓库边界

- 真实 `config.json`、`project-map.json` 放在 `~/.config/git-weekly-report/`，不提交。
- 仓库只保留 `*.example.json` 作为配置示例，不包含真实项目名和邮箱。
- 模板只保留空白“个人周报（模板）”工作表，不包含其他同事的姓名和数据。
- `commits.json`、`report.json`、生成的 `.xlsx` 都是本地产物，不提交。
- 示例中的邮箱、项目名、提交标题必须脱敏。

## 10. 后续扩展

- 多周详细周报：按周分块，复用 `commits.json`，新增 renderer。
- 手工补充项：会议、方案、客户支持等无 commit 的工作，通过独立输入文件合并。
- 团队统计：支持多作者和按人分组，但需要新的权限与隐私约定。
